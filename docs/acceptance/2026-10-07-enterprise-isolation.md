# 企业隔离验收记录

日期：2026-10-07。开发与发布只涉及阿里云，原 WSL2 与 Mac 项目未改动。

## 已实现的边界

- PostgreSQL 140 张企业业务表强制 ENABLE/FORCE RLS；每家企业使用由完整 tenant_id 派生的独立无特权登录角色。策略依据真实数据库身份，不接受客户端 GUC、请求头或前端企业 ID 作为授权。
- 保留应用查询 tenant_id 条件并关闭旧无过滤查询接口。运行账户无 owner、BYPASSRLS、角色成员资格、建库建角色、TRUNCATE 或转授权权限。
- API、scheduler、notification、启用的邮件反馈与独立邮箱入口都在服务开始前检查隔离，管理账号或未完成隔离的配置拒绝启动。
- 迁移与运行凭证分开；可信配置 CLI 默认 dry-run，显式 apply 后先验证受限连接，再原子写入私有配置。已有配置只验证，不旋转密码；未关联同名角色拒绝覆盖。独立邮箱的显式 init/migrate 复用同一配置过程，普通 start 不自动迁移。
- 固定企业 API 容器只接受受信装配的独立 tenant、engine、认证实例与 cookie；父生命周期验证全部企业后才接受请求，失败关闭并释放资源。
- Obsidian connector 可从已授权文档生成企业/员工/任务专属只读资料快照；核验哈希，拒绝混合企业、路径穿越、软硬链接和恶意规则文件，并按自身创建的对象清理。

## 验证记录

1. 本机相关 24 组单元测试：470 passed、1 skipped，22.24 秒。跳过项是 Linux /proc 进程时间专属回归；不将其算作通过。
2. 独立真实 PostgreSQL 5 项测试：最终批量查询版本 5 passed，16.53 秒。覆盖真实双登录角色、遗漏 WHERE、GUC 篡改、跨企业读写、SET ROLE、TRUNCATE、额外策略/权限篡改、并发连接，以及 0070→0069→0070。临时数据库与角色清理完成。
3. 变更的 33 个 Python 文件 Ruff 通过；结构自检通过。
4. 独立复审发现并修复：管理账号兼容分支静默跳过门禁、邮箱两表未注册、独立邮箱配置无受限角色入口、旧版本不接受新增配置字段的恢复问题。
5. 真实 PostgreSQL + HTTP 认证/同名产品/跨企业 cookie/CSRF/并发联合验收：1 passed，187.38 秒；真实双企业使用相同登录名和密码、同名同 ID 产品、双向 cookie 重放和改名重放、CSRF、并发读取、单方退出均通过。临时数据库已删除。
6. 云端正式迁移、运行角色切换和上线检查：尚未执行。当前运行版本仍为 20261007-model-v4。

## 验收中遇到的问题

- 在小内存云主机运行完整接口测试曾造成短时 SSH/HTTPS 无响应；恢复后保持旧生产版本，没有重启或恢复业务备份。后续完整应用测试改在 Mac 执行，通过仅绑定本机回环的 SSH 隧道访问独立临时数据库。
- 真实 PostgreSQL 检查暴露并修复了邮箱表覆盖遗漏、内部 char 类型需转 text、权限函数参数需明确 name/oid 类型的问题。
- 跨地区逐表权限查询耗时较长，改为一次批量查询并严格核对全部 OID、每表 DML 和危险权限；授权也改为一条针对固定完整表清单的 GRANT。

## 本次能力范围

完成的是企业数据隔离基础与当前部署加固。企业开户/邀请、xue 平台管理界面、四个指定账号、企业资料上传检索 UI、按已发布产品驱动获客、Codex 网页任务接线仍是后续功能，不能以本次隔离验收冒充已经完成。旧共享 CLI vault 未开放为多企业入口。任务快照本身不是操作系统沙箱，后续 Codex 接线仍必须限制进程文件系统与外部工具权限。

平台管理员将来的只读查看不得成为 JSLT 业务或 AI 的数据来源。本次没有模型调用、邮件发送、业务清库或新增数据备份。
