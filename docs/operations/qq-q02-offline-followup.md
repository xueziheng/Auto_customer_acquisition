# Q02 证据核对后的最小离线收尾

这是 v3 的历史结论。v4 对候选停止和 multipart 做了有限离线实现，当前规则见 [v4 准入说明](qq-v4-mime-admission.md)；实际地址语法仍缺证据。

本轮仅修改隔离副本。没有邮箱采集、真实模型、发送、部署或生产迁移。

## 历史证据与来源

2026-10-16 的已存头部核对证明：Q02 收件方导出的初始邮件，严格展开折行后，原幂等标记唯一对应原 SENT attempt；实际投递 Message-ID 精确等于已归档回复的 In-Reply-To。这只证明这一次投递的关联。不能推出将来均保留标记、发件箱保存同一编号或自动采集已实现。

`verify_sent_alias` 现在强制调用者提供 `source`：

| 类型 | 解析结果可用于 | 能否进入现有 Sent 采集门禁 |
| --- | --- | --- |
| `recipient_export` | 收件方导出头的历史关联核对 | 否，在授权/数据库访问之前拒绝 |
| `sender_sent` | 发件方 Sent 头的候选核对 | 仍须原 Gateway 成功调用、原件哈希/大小、租户/用户/attempt 精确绑定及当前授权 |

来源是受信调用方的契约字段，不是能自证来源的签名。邮件内容不得设置它，不能把手动导出重标为 sender_sent。测试中的成功工具行是隔离空库的合成夹具；不是实际 Gateway 回执。`email.qq.sent_alias.read` 仍未注册、采集器和受信启动装配仍未实现。本轮不创建新的生产证据类型或数据库迁移。

## 折行与原件保留

只移除后接 SP/HTAB 的 CRLF，随后仅去掉值两端的 SP/HTAB；不删除内部空白。标记必须严格符合项目 token 格式并等于 canonical Message-ID 的标记。解析使用原始字段值，不允许 encoded-word 解码把异常形式变成合法标记。孤立折行、裸 CR/LF、控制字符、字段名空白、重复绑定字段、正文混入以及多个候选仍拒绝。

返回的 `raw_headers` 与 SHA256 始终对应原始字节，不会保存成规范化重建件。固定样本只复现 Q02 的折行形态；没有复制、改写或上传真实 eml，也没有补造其缺失的 Date/References。

## Q02 回复兼容性评估

已存头部摘要记录：multipart/alternative，From 和 To 各有两个 InvalidHeaderDefect，无重复的被检查头。新测试使用同类别/数量缺陷的合成地址，不能当作真实地址字符串逐字重现。没有读取真实回复正文和 MIME 子部分。

| 检查 | 对 Q02 已知形态的影响 | 本轮处理 |
| --- | --- | --- |
| 原编号/alias | 引用编号关系已通过历史证据核对；缺自动采集/当前试验授权 | 不注册历史 alias，不重放 |
| `reply_headers` 地址字段缺陷 | 任一 From/To defect 即返回 None；即使能提取正确地址也不接受 | 保留拒绝；固定样本复现 |
| 实际 reader 顺序 | 地址失败先被当非候选跳过，不进入 MIME 门禁；返回的建议游标可能前进 | 准确记录现有行为，未改代码，也未推进真实游标 |
| multipart 顶层 | 地址有效时才会到此，按 `mime_structure_unverified` 停止；不能从顶层推定有/无附件 | 不放开、不改变读取前门禁 |
| 附件/Bcc/完整性 | 原附件、Bcc、大小、UID、正文头一致性检查保留；真实内部结构和正文完整性未在本轮验证 | 沿用原测试；不据解析成功宣称无附件 |
| 共享 MIME 解析器 | 标准 alternative 可解析，但带附件时可能跳过附件后仍为 CANDIDATE | 解析成功不能替代准入证据 |

两个独立阻断都未修复，不能把本轮称为真实收信兼容完成。

## 需要另行评审的最小方案

1. 先取得精确地址头的脱敏、可复现语法证据，判断是无歧义编码错误还是存在多个解释。不全局忽略 InvalidHeaderDefect；如确需容错，仅限定具体语法并重核单地址、无组/多值/注入、双方精确匹配，保留原字节与缺陷审计。应同时评审“跳过并推进建议游标”是否要改为明确停止；本轮不扩大解析规则。
2. 对 multipart，须在原候选头阶段取得受限 BODYSTRUCTURE，限制深度、部件数、嵌套 message、类型、disposition/filename、总字节与响应完整性，并与后续一次 MIME 读取交叉核验。缺失/截断/歧义停止，不能先读取完整附件再决定拒绝。该协议扩展尚未实现或授权真实采集。
3. 补齐隔离完整测试运行时和受信采集装配后，才可讨论全新单封真实试验。原 36 项 setup errors 继续列为未验收，不启动全局 Docker、不下载依赖或改系统设置来绕过。
