# 获批客户自动准备运行说明

此功能从显式批准的客户开发范围开始。企业管理员在原开发任务编辑器选负责人、填写真实处理依据引用、选择一至五份本企业已确认资料，再走原精确版本批准。搜索时选择这个批准版本；不选范围继续原搜索及人工操作。保留既有管理员搜索/分配权限，负责人可为在职经理或销售。

准备使用现平台模型连接、现网页和联系人来源；没有任何新默认密钥、来源开关或验证探针。企业确认资料用于内部适配，不表示正式产品发布或客户可见许可。当前仅支持法人企业的职务邮箱与明确 legitimate_interest 范围断言；系统不声称已经完成法律评估。

## 启动兼容

原 scheduler 参数 `--profile <现profile路径> --model-settings <现模型配置路径>` 保持可用。可额外传 `--hunter-customer-settings <现Hunter元数据路径>`；省略时只查找 profile 同目录已存在的 `hunter-customer-settings.json`，与 API 沿用同一文件，不创建或复制配置。文件内凭证来源仍走原惰性 resolver。启动只读取元数据，不解析 Key，不访问 Hunter，不代替真人 provider.hunter.validate。

复用当前企业运行库与独立平台控制库配置。需先按原迁移流程升级至当前 head（Task4 新增0089–0091），应用启动不迁移生产库。准备消费者与原库存驱动共用 scheduler singleton；同一数据库不可启动竞争的临时迁移测试。

Hunter 当前配置必须已有真实验证事实，且与安全配置摘要一致；只有取得原 singleton、双工具实际装配完成后才标记 runtime_composed。既有联系人组合可直接复用；缺失或旧认证状态不足显示“验证服务未就绪”。网页原件需要专用 bounded transport，不能回退无界读取。

customer_preparation 沿既有平台模型目录和企业/员工/configuration_version 授权解析，不需要另建同名能力绑定或另存 Key；平台禁用、版本过期或 export 未授权仍拒绝。保留当前 Codex CLI 调用方式；本功能不改变搜索 provider 选择。

## 状态和恢复

客户详情显示等待、处理中、固定阻断或已验证并入组，并链接原批准范围和企业资料。入组不代表发送。`automatic_send_enabled=False` 仍可完成合规准备和入组，实际 email.send 不运行；准备也要求真实可用 sender，不能用虚构身份占位。

每项只接受原请求/分配的固定授权和幂等键。进程重启可恢复未派发阶段；已经派发但结果未知显示待核对，不重新搜索、调用模型或验证邮箱。此版本不提供自动解除未知围栏或随意重新排队按钮；运维应核对原工具账本及准备状态，不用更换幂等键强行重试。撤销/修改范围、离职、归属转交、资料变化及国家政策撤销都会阻断后续步骤，发送前再次读取当前事实。

合成验收覆盖实际 API、Postgres 租约、原 singleton、Gateway、原件、验证及入组，外部网页/模型/Hunter传输替换为确定响应；它不表示真实来源、真实模型输出、实际邮箱送达或生产部署已验收。开发中没有改变现有配置、密钥、来源额度或生产数据。
