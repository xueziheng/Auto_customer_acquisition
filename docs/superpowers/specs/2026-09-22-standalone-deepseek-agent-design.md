# 公司统一部署的 DeepSeek Trade Agent 设计

日期：2026-09-22。
状态：用户已批准设计与首批实施。首批实现已完成，最终回归及独立审查结果见[验收记录](../../operations/2026-09-22-builtin-deepseek-acceptance.md)；真实网关连接探测已通过；真实产品全流程和公司共享部署尚未验收。
源码基线：`codex/web-internal-pilot`，`bae9c6c1dd7368a5fc90c1bd476a8b6f565aa921`。

## 1. 已确认的目标与交付口径

用户明确要求：给项目接入大模型 API，让用户直接使用项目，不依赖 Codex 或其他外部 Agent 产品；
认可公司统一部署、管理员一次配置、员工登录使用；指定首版服务商为 **DeepSeek**。

交付后的正常路径是：管理员准备服务器和服务配置 → 员工打开公司网址登录 → 在产品内提出目标、
补充信息 → 系统按权限生成可审阅的提案或回答 → 确认后由后台执行 → 查看进度、来源证据与结果。
浏览器关闭、Codex 退出不停止已被正式接纳的业务任务。服务器停止会暂停推进，恢复后按持久状态继续。

本次仍为**一个公司、一个租户、多个员工**，不建设多公司 SaaS、租户自助开通、订阅或积分钱包。
沿用根 [AGENTS.md](../../../AGENTS.md) 的九条硬边界和逐次人工审批，模型不会获得管理员身份。

“直接使用”指员工不安装开发工具、不配置模型密钥；不意味着首次部署无需配置模型账户、业务政策、
搜索服务和邮箱。没有配置的能力在产品内明确显示缺项。

## 3. 方案选择与分批边界

| 方案 | 收益与代价 | 选择 |
| --- | --- | --- |
| 在现有 TradeOS 内接 DeepSeek、会话和确定性工作流 | 复用业务域、证据和审批，需补持久交互与共享部署 | 采用 |
| 通过外部 Agent 平台运行，再调用 TradeOS | 增加另一个运行和权限体系，仍依赖外部 Agent 产品 | 不采用 |
| 先建设通用模型路由及任意工具 Agent 平台 | 扩大范围，无法尽早验证贸易机会产出 | 不采用 |

整体分三批，每批单独设计细化和验收，不用某一批完成代替整个目标：

1. **内置 DeepSeek Agent**：真实模型配置、模型网关与用量、持久会话、权限内查询、多轮研究提案、
   真实 research_only 执行。以下第 4–9 节为这一批的详细设计。
2. **公司共享运行**：同源 HTTPS、共享认证配置、可重复部署、持续运行和恢复。第 10 节固定交付约束；
   实施前另写这一批的具体部署规格。只有这一批也验收后，才可称员工通过公司网址直接使用。
3. **真实业务能力逐组接入**：联系人、已批 Campaign、发信、入站和回复识别优先；寻源与报价按已有
   Linux 解析和审批条件接入。每组分别记录配置、真实验证及可用状态，不能由 DeepSeek 成功推导已就绪。

本书面设计供审阅，不是逐任务实施计划。首批完成不等于邮件已发送、客户已验证或系统已生产部署。

## 4. 执行架构与职责

```text
员工浏览器（指挥中心 / 原业务页面）
                ↓ 同源认证 API
      Agent Session / Agent Turn / Run
                ↓ 持久工作流与当前身份核验
     Trade Manager + Context Builder + 技能 / 护栏
                ↓ 明确的单步请求
       Tool Gateway → DeepSeek / 搜索 / 页面等 Connector
                ↓ 验证输出、登记证据与用量
      领域服务 / Change Set / DirectiveProposal / 审批
                ↓ 原 scheduler 推进业务流程
           Run 结果与站内通知
```

- 大模型负责理解、澄清、提案和解释；workflow 负责执行次序、等待、重试和恢复。
- 新建 `domains/assistant/` 只管理员工 Agent Session/Agent Turn、归属、状态和安全结果引用。
  不把员工内部对话塞进存放客户邮件的 `domains/conversations/`，也不冒充客户明确需求。
- 跨域读取和动作组合放在 `workflows/` 或 `agent_runtime/`，只消费已有公开服务。
  新域不导入其他域，SQL 实现仍在 `infra/db/`。
- 新增持久交互 workflow，注册到原 scheduler。每轮只有一个 canonical Run，浏览器请求只负责接纳、
  返回身份和读取状态；长模型调用不依靠浏览器 HTTP 连接存活。
- 没有生产任务来源的通用 Agent Worker/Browser Worker 继续 disabled。公司入口可用的内置 Agent
  由上述明确执行者提供，不把 worker 是否存在当作“智能”是否存在的依据。
- 所有跨层契约、新增域、共享认证和模型网关组合先留 ADR；实施时更新 GLOSSARY、目录规则和能力矩阵。
  本批设计只增加文档，不预建空目录或假实现。

## 5. DeepSeek 接口与配置

### 5.1 官方接口核对

2026-09-22 核对的官方文档确认：DeepSeek 提供 Responses API，服务地址为
`https://api.deepseek.com`；该接口无服务器端对话状态，历史须由调用方组织，不能依赖
`previous_response_id` 或 `background`。内置搜索等工具不随这一接口自动提供。
来源：[Responses API 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)。

首版选用 Responses 格式适配现有窄端口；只发送经兼容测试确认的参数。JSON 输出仍需本地严格验证，
响应 `status` 不完整、空正文或格式错误均不得落成成功业务结果。
来源：[Responses 接口定义](https://api-docs.deepseek.com/api/create-response/)。

用量以接口返回的 usage 为事实来源；本地上下文估算只用于限长，不视为实际账单。
来源：[Token 用量说明](https://api-docs.deepseek.com/quick_start/token_usage/)。

### 5.2 Connector 与模型选择

- 新增 `connectors/deepseek/`，固定官方 HTTPS endpoint，不接受员工输入的 base URL，不跨站跟随带凭证重定向。
  采用已安装 SDK 的兼容传输，并关闭 SDK 隐式重试；依赖名称不意味着调用 OpenAI 服务。
- 在公司入口只注册 DeepSeek。模型 ID 是管理员明确配置、验证过的值，不硬编码历史别名，不自动切换
  服务商或更贵模型。保留既有 OpenAI Connector 仅供其原有配置使用，不作为失败回退。
- 首版按结构化响应处理路由与提案，不启用模型自由选择任意函数的循环。
  模型输出的是受支持的动作请求，业务参数和当前权限由代码重新校验。
- 首版显式关闭 thinking（`reasoning.effort=none`），连接测试核验配置模型支持该模式和 JSON 输出；
  不依赖服务商默认模式，也不在失败时自动升级推理模式。后续变更同样经过评估与配置版本更新。
- 推理过程不进入用户消息、业务证据或日志；只保存校验通过的最终结果及安全用量元数据。
- 模型或 prompt 改变必须重跑现有业务 evals 及本批多轮提案 evals，不能因 API 兼容就假定业务能力等价。

### 5.3 管理员配置与启用

管理员通过部署端的受信配置入口保存密钥，优先复用受限 secret 文件/环境引用解析模式。
密钥不经 Agent 聊天提交，不写入普通业务表、前端包或浏览器存储；员工不能查询值或任意 secret ref。
Web 设置页只操作非秘密配置和显式连接测试，显示 provider、模型、配置版本、验证时间及固定失败原因。

必须显式配置：模型 ID、凭证逻辑引用、单次输入大小/输出上限、超时、模型调用次数限制、租户与员工并发上限。
调用次数窗口使用 UTC，租户总量与每员工上限同时执行；未配限额不自动试用真实模型。
数值由管理员提供，测试阈值不会写成公司默认政策。

连接测试使用固定无业务信息的短输入，经同一 Gateway 和配额执行。界面先说明会产生一次真实模型调用，
操作者点击测试才执行；没有启动时自动测试。配置更新令旧验证失效，后台实际装配的版本必须匹配。
凭证错误、余额/额度不足、限流、协议错误和网络结果未知分别显示，不以“已保存”冒称“可以使用”。
首版配置更新采用受控重启，界面显示待重启；不承诺跨进程无中断热切换。

## 6. 模型网关、记账与恢复

新增模型工具 manifest、handler、检查适配和持久用量端口，复用原网关管线，不在 `pipeline.py`
按具体模型或 tool ID 分支。模型调用至少经过 tenant、permission、playbook、idempotency、rate_limit；
各检查只消费当前公开事实。playbook 检查中的模型数据外发许可由公司显式启用配置提供，不能因业务
市场政策尚未设置而完全阻断产品使用说明，也不能绕过研究步骤自己的市场政策门禁。

每次模型调用绑定受信 tenant、当前员工、Run、Agent Turn（如有）、能力、模型配置版本和调用序号；
这些字段不由模型生成。API 原有即时提案路径也必须建立受信 Run/调用绑定后注入网关适配器；公司入口
中缺绑定的旧调用返回明确不可用，不回退到直接 SDK。新对话路径不通过 API 自己调用自己的 HTTP 路由。

模型请求只在授权通过后由 handler 构造 Connector；密钥仅 Connector 解析。提示词、业务原文和完整
响应不能进通用 tool ledger/outbox/log。经校验的会话内容进入受权限控制的会话存储；账本只存安全引用。

用量账本保存配置版本、provider/model、调用与 Run 身份、实际输入/缓存/输出 tokens、耗时及完成分类。
缺失 usage 标为 unknown；账本不保存原始推理文本。可信费率齐全时才由 Decimal 计算模型成本，费率带版本、
币种和来源；否则只显示 tokens/调用次数和“金额未知”。模型费用不等于完整获客成本。

限额在调用前持久、原子预留，覆盖所有采用这一模型入口的 API/worker 及连接测试。两个员工争抢最后
一次额度最多一个进入 Connector；进程重启不能恢复已用次数。首版硬限制是调用次数、并发、输入大小和
输出上限，不把近似 tokenizer 或事后金额显示当成精确人民币/美元硬预算。
额度和调用 claim 使用独立锁身份，不在独立数据库连接重新锁住工作流引擎已持有的 Run 行。

故障分类及行为：

| 情况 | 行为 |
| --- | --- |
| 尚未进入 Provider 的配置、权限、额度拒绝 | 明确拒绝，不记为已执行模型请求 |
| 确定的参数/认证错误 | 固定错误分类，等待修正，不自动重试 |
| 限流或明确可重试服务错误 | 有界等待且服从 Retry-After；仅在可证明安全及额度允许时重试 |
| 已发送请求后超时、连接断开、进程崩溃或结果落库失败 | 标记结果未知，保留调用预留和原调用身份，不自动再次请求 |
| 模型输出不完整或未过 schema/护栏 | 不执行业务动作；已发生调用照实计量，不反复自动“修复”消耗费用 |
| 同一员工同一幂等键、相同请求重放 | 返回已有轮次/结果，不能创建新的模型调用或业务结果 |
| 用户选择重新生成未知/失败结果 | 新增显式 attempt 并重新占用额度；保留旧 attempt，不更换键掩盖重复费用 |

限流错误不能简单等同于“未计费”；只有 Connector 对执行确定性的证据足够时才释放预留。
无论模型能否重试，下游业务动作仍有自己的幂等与审批，重生成文本不等于重发邮件。

## 7. 员工对话、数据和权限

### 7.1 会话与轮次

Agent Session 绑定 tenant、发起员工、创建时间和版本。默认仅会话发起人可读；老板能看公司业务记录
不等于可以读取所有员工的内部会话。本批不提供会话转交或共享。

Agent Turn 保存输入、当前状态、Run、消息来源引用、结果引用、模型调用引用和时间。
推荐轮次状态为 `queued/running/awaiting_input/proposal_ready/completed/blocked/failed/unknown/cancelled`；
它们描述内部交互，不替换 DirectiveProposal、审批或业务 Run 的原有状态。
`awaiting_input` 和 `proposal_ready` 表示本轮已交付提问或提案，不占用执行槽；后续输入产生新轮次。
提案的确认及业务 Run 状态在关联卡片中实时读取，不回写历史模型文本为新的事实。

接纳输入和持久执行意图在同一事务提交；使用唯一键建立 canonical Run，并保留可恢复的绑定状态，
处理“事务成功但 HTTP 回执丢失”及“已 start Run 尚未绑定”窗口。同一会话最多一个执行中的轮次；
并发输入返回冲突和当前轮次，不隐式重排。数据库查询始终 tenant-bound。

### 7.2 支持的任务

首批公开给老板、经理、销售的业务动作是：

1. 解答产品使用问题，依据版本化产品说明；不声称完成任何业务写入。
2. 查询、解释当前有权访问的 Need、Trade Opportunity、Handoff 和 Run，附可核对的对象链接。
3. 老板通过多轮交流补齐研究目标、范围和预算，生成 research_only DirectiveProposal。
4. 展示正式提案并链接原确认动作，读取其真实执行进度与结果。

其他合法员工角色可使用产品说明；业务上下文和工具只在其既有领域权限完成适配后开放，界面明确列出
当前可用能力。不把 sourcing/finance/viewer 强制转换成 sales，也不把员工输入当老板指令权限。
首批不提供任意 shell、SQL、文件路径、URL 抓取、批准审批、修改发件身份或直接发送工具。

### 7.3 多轮研究提案

历史输入中的国家、品类、排除项、研究预算和原有必填字段须保留到具体 Agent Turn 的出处。
字段不全时返回要补充的问题，不能用模型默认值、旧测试资料或其他员工会话补齐。
可引用当前老板已确认的政策值，但提案必须显示来源版本和本次采用值；未配置就是缺项。

模型先返回受限结构：需要澄清、允许的只读动作、研究提案或解释；代码校验并路由单步动作。
查询规划可由模型生成，但市场与额度不得越过明确确认的边界。提案汇总时显示原话、理解、证据来源、
三条研究线路、预计调用预算及禁止外发的执行范围。

聊天里的“可以”“继续”不自动代替正式审批。对执行提案使用当前用户可见的精确确认控件；该控件调用
既有确认语义并产生审计。确认后独立 research Run 由 scheduler 推进，Agent Session 只保存引用。
研究完成最多产生有证据的 Demand Signal / Need Hypothesis，不直接声称 Validated Need 或成交。

### 7.4 当前权限和输出

每轮装载上下文、进入模型、应用输出和读取结果时都重新检查当前员工及对象权限，模型工具集合是权限
与本轮能力的交集。跨租户、停用、客户归属变化不能因旧会话继续访问。
模型生成的摘要记录其依赖对象；重新查看或复用历史时，相关对象已不可见则隐藏整段受限摘要并排除其
派生总结，不从旧文本重新泄露。后台审计保留原记录，产品视图按当前权限裁剪。

员工描述、客户原话、公开证据和模型推断在存储与 UI 分离；员工在聊天中写“客户要买”不能绕过
原 Demand 验证端口直接建已验证需求。模型不能提供最终金额或概率。上下文超限时保留规则和明确指令，
仅裁剪允许裁剪的背景并记录，不能暗中删除审批或排除条件。
输入凭证标记检查先于会话正文持久化与模型发送；拒绝时不在错误中回显原文。网页、客户消息与文件
内容只作为不可信资料，不能提高工具权限或覆盖系统规则。解释中的事实必须绑定本次有权读取的来源，
来源缺失则返回缺项，不能借助模型常识编造公司业务事实。

## 8. Web 与 API 契约方向

新入口放在现有指挥中心，包含会话列表、交流区、提案/任务卡和结果证据。API 的请求与返回 DTO
在对应域定义，Web 类型从 OpenAPI 生成。候选资源路径为 `/agent/sessions`、其下的 `/turns` 和
轮次详情；确定业务动作继续复用原业务服务和审批接口，不另建万能 `/execute`。

- 创建轮次接受正文、允许的对象引用和客户端幂等键；tenant、actor、role、工具权限全部由后端决定。
- 接纳后返回 `202` 和持久会话/轮次/Run 身份。默认轮询固定间隔的安全状态，刷新能够恢复，不依赖 SSE。
- 首版展示“正在理解/等待补充/等待确认/执行中/失败/结果未知”，最终文本和动作卡只在护栏通过后出现。
  不把未完成的模型 token 流直接显示为事实或执行指令。
- 停止生成是有权限的取消请求，阻止后续未开始步骤；不能撤销已发出的模型请求或已发生的业务动作。
  会话取消与已确认业务 Run 的停止分别展示，不能用关闭对话框假装终止研究。
- 身份切换、权限撤销和退出时清理会话及旧请求结果；会话标题、列表预览、错误和通知也不能泄露内容。
- 设置页展示模型、研究、联系人、邮箱等各自状态和缺项；运行进程 ready 不等于业务能力 ready。
- 内置 Agent 与模型配置使用新增的明确能力投影，按 ADR 扩展共享契约；不把原通用 Agent Worker 的
  disabled 状态改名为 enabled 来掩盖执行来源差异。

## 9. 首批真实研究接线

使用原 `ResearchRuntimePorts`、quota、原始网页读取、Artifact Store 和 `demand_discovery` 工作流，
把 DeepSeek 以统一受计量端口注入。Tavily 的凭证、免费账户确认、剩余额度和市场政策独立配置；
DeepSeek Key 不能替代搜索 Key。免费状态或调用结果未知时仍失败关闭，无付费搜索回退。

没有搜索配置时，模型对话、权限内查询和草拟研究提案可用；执行控件准确说明缺项。提案已经确认
不代表外部研究已开始，以 canonical Run 为准。补配置后仅按原提案/幂等身份恢复合法执行。
旧 `research_source_acceptance` 仍只验来源，不作为完整模型研究的成功证据。

首批实网验收必须从产品内老板输入开始，经过真实 DeepSeek、真实搜索和原始网页证据，到正式 Signal/
Hypothesis 和 Run 展示；不能由助手在 Codex 中调查后手工插入结果代替。发信和报价调用数必须为零。

## 10. 公司共享运行批次的固定要求

- 新建显式 company deployment profile，提供 Linux 服务器部署产物；不把 `pilot.py` 的 loopback
  网络限制简单删除或改成公网监听。API、scheduler、notification 各自独立装配，不互导进程模块。
- 浏览器与 `/api` 同源 HTTPS；只信部署时指定的 canonical origin 和明确代理边界，拒绝任意 Host、
  Origin、伪造转发头和开发员工头。Cookie 为 HttpOnly、Secure、SameSite，明确路径且不设宽域共享。
  原会话撤销、CSRF、登录限流和当前员工权限保留；cookie 名不再假定 origin 必有端口。
- 生产静态 Web 随服务交付，员工只需浏览器与账号；无默认密码或公共注册。管理员首次创建账号仍使用
 受信运维入口，不在日志或模型中传递密码。
- 部署包含持久 PG、对象存储、三个应用进程、HTTPS 入口、重启策略和健康检查；后台由部署系统维持，
  不依靠 Codex 终端或某位员工浏览器存活。scheduler 继续持同一单副本锁。
- 固定构建版本和依赖；显式迁移、停机窗口、持久卷保留、备份和恢复到新目标均有操作说明及实际测试。
  实际服务器/域名/证书和备份位置是部署输入，未提供时可以完成本地容器验收，不能声称公网已部署。
- 按浏览器实际验收范围报告兼容性，保留 Web Locks 必需条件；共享认证、模型调用并发和持久任务恢复
  需要在公司 profile 下重跑，不能借用本机 pilot 的旧通过记录。

## 11. 明确暂缓的能力

本项目总体目标仍包含真实需求验证与人工接管，但以下能力不因本批模型接入而自动开放：
未经独立验收的 Gmail/Hunter 真实运营、完整 Linux 报价/PDF 组合、供应商联系、自动成交、
Catalog 培养消费者、桌面端、本机浏览器登录态操作、多模型路由、多租户 SaaS。
它们按各自公开契约和业务授权接入；首批 UI 不展示假成功按钮。

已经明确的负责人持续归属、接受后停止催接管仍保留；不重启用户已暂缓的“退回 Agent”需求。
接管 SLA、价值分档、市场政策等现存缺项不能为方便初始化而代填，需要在各自配置路径显式处理。

## 12. 验收标准

| 编号 | 必须实际证明的结果 |
| --- | --- |
| A1 | 新 Connector 请求只到固定 DeepSeek endpoint；认证失败、余额/限流、超时、空/不完整 JSON 均返回正确安全分类，无默认 OpenAI 回退 |
| A2 | 所有新模型调用都有 Gateway 执行记录和受信用户/Run；凭证、原文、完整响应不出现在 ledger、日志、错误、追踪和生成前端资源 |
| A3 | 公司/员工额度并发与重启后保持，未知执行不退款或自动重试；重复提交不重复模型消费，未知 usage 不写零费用 |
| A4 | 老板、经理、销售各自会话隔离；跨租户、停用、归属改变、历史摘要与新旧浏览器请求均无越权 |
| A5 | 自然语言缺字段时能多轮澄清，参数来源可追溯；模型猜预算/编造来源/概率/最终金额/越权工具调用均被拦截 |
| A6 | 研究提案由当前老板精确确认；普通员工不能确认，旧提案/旧政策按原规则拒绝或要求复核 |
| A7 | 在预算授权内跑通真实 DeepSeek＋真实研究来源→页面 Artifact→Signal/Hypothesis→Run 展示，联系人/发信/报价调用数为零 |
| A8 | 浏览器关闭、API/worker 重启、重复回执和模型响应后落库失败均有真实受控故障验收；不会把未知执行当未执行 |
| A9 | 公司 profile 在同源 HTTPS 下支持两名员工独立登录，撤销、CSRF、代理/Host 校验、Secure Cookie 和停用回归通过 |
| A10 | 不运行 Codex/外部 Agent 软件时服务可独立启动，后台任务继续；完整 stop/start 保留资料，备份恢复到新目标后能核对 |
| A11 | Web 1440px/390px 下能完成聊天、提案核对、查看证据与故障恢复；配置缺失/权限不足/执行未知显示准确 |
| A12 | 结构自检、受影响类型/静态门、后端与Web回归、OpenAPI一致性及模型/prompt evals通过；受控、真实模型、真实来源、真实运营、共享部署结果分栏 |

首批为 A1–A8 与其相关的 A11–A12；公司共享批次完成 A9–A10 并重跑组合验收。A7 未运行时只能交付
“模型和研究接线的受控版本”，不能称真实研究已经可用；A9–A10 未运行时不能称公司共享版完成。
所有测试记录绑定同一源码版本，局部与历史全量结果不累加。

## 13. 实施准备与不确定项

目前没有读取真实凭证、连接模型账户、消耗模型额度、发送客户信息或部署服务器。
用户选择 DeepSeek 是技术选型；真实调用前须由管理员配置受信凭证及明确用量限制。
真实研究另外需要国家/品类/搜索预算和当前已批准政策，首个真实业务闭环仍需公司对外资料及联系人等输入。

实施从较新源码建立独立 `codex/` 工作分支，保留当前工作树已有的尼日利亚研究文档修改。
依次细化首批接口与迁移 ADR、编写首批实施计划、执行和验证；之后再细化公司共享批次。
不在这一份设计内一次重写所有业务能力。根九条硬边界不作修改。
