# AI 外贸潜客开发系统设计

## 目标

构建一个单用户、本地优先的 AI B2B 邮件获客 MVP：系统根据已授权产品和市场机会寻找海外公司与联系人，以真实销售人员身份用英语执行首封加三次跟进；出现明确采购动作时，有授权报价就先报价，否则立即转人工，并把 Gmail 线程与中文摘要交接到 Obsidian CRM。

## 已确认业务规则

- 系统服务自营贸易公司，不是对外 SaaS。
- 两类活动并行：明确产品活动、通用中国寻源活动。
- 现有 31 个 Obsidian 产品进入候选池；目录外机会必须先批准，再用邮件验证兴趣。
- 公开网页优先发现公司，付费联系人数据只补全高价值候选。
- 所有客户邮件使用英语；内部 UI、摘要和任务使用中文。
- 使用真实销售人员身份和个人 Gmail；每天新增触达默认 30 封、硬上限 50 封。
- 无回复序列固定为 D0、D3、D7、D14；拒绝、退订、永久退信立即停止。
- 询价、索要目录/规格/样品、提出采购需求、要求会议或明确继续讨论，均视为合格意向。
- 意向出现后停止常规自动序列。有启用且条件匹配的报价规则时发送报价并转交；否则直接转交。
- 人工接管目标为 Gmail `AI-Outbound/Handoff` 标签和 Obsidian CRM，SLA 为 1 个工作日。
- 第一阶段核心指标是合格潜客转交数；首个 4 周只建立基线。

## 系统边界

Obsidian Vault 是私有知识源。同步程序只读取用户允许对外使用的产品图片、参数和说明，排除 `conflict`、待确认和没有证据的商务承诺。运行层使用本地 SQLite 保存活动、候选公司、联系人、邮件线程、序列、意向、报价权限、抑制名单和审计日志。外部研究和 Gmail 操作由 Codex 周期任务调用 Web 与 Gmail 插件完成，应用本身不保存 Gmail OAuth 密钥。

## 架构

```text
Obsidian 产品库 ──授权同步──> SQLite 授权产品
                                     │
市场研究任务 ──Codex/Web──> 候选公司/联系人 ──审批活动──> 邮件序列
                                                           │
Gmail 插件 <──周期动作/结果── Codex 自动任务 <──> SQLite CLI
                                                           │
                              回复分类 ──> 授权报价或人工接管
                                                           │
                                      Gmail 标签 + Obsidian CRM
```

## UI

采用已选择的 B「智能收件箱」：左侧导航与 Gmail 状态；顶部四类线程指标；中部线程列表；右侧英文邮件、中文摘要、机会信息和人工接管操作。所有演示数据必须标记 `DEMO DATA`；真实模式不显示虚构指标。

## 安全与失败策略

- 只绑定 `127.0.0.1`；不把 Vault 原始资料发送到外部搜索。
- 密钥只通过环境变量或 Gmail 插件授权，不写 SQLite、日志或前端。
- 所有外部动作使用幂等键；重复周期不得重复发信或创建重复 CRM 记录。
- 退订、退信、投诉和人工接管是强停止状态。
- Gmail、Web 或 Vault 暂时不可用时记录失败并重试，不跳过审批、不猜价格。
- 高风险产品、国家或客户命中阻断规则时暂停活动，等待人工处理。

## 验收

- 本地 UI 可查看活动、线程、英文邮件、中文摘要和接管任务。
- SQLite 能持久化完整状态，重启后不丢失且不会重复执行动作。
- Fixture 模式完成“研究候选 → 发信 → 回复 → 意向 → 报价/转交 → Obsidian 导出”全链路。
- Gmail 插件安装并授权后，真实模式可读取线程、发送邮件、加标签和停止自动序列。
- 首个真实活动必须由用户批准，且默认每日新触达不超过 30 封。
