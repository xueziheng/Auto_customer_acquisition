# 企业客户归属与日常界面精简

用户在 2026-10-14 已确认并要求实现：平台管理来源，企业管理员搜索并分配，员工跟进自己获分配的客户。

## 权限与流程

- 平台 xue 继续独占获客数据来源、访问方式、连接配置、来源策略和交付额度管理。企业侧不提供来源配置或选择来源入口。
- 企业 boss（jslt）可以手动找客户、看本公司待分配客户、将客户分配给本公司在职员工；普通 manager/sales 不再允许搜索/领取，客户范围限自己。管理员可分配给自己。
- 搜索先取得公司客户，新增交付的 employee_id 为空，之后分配不重复计费。历史已有 employee_id 的记录保留归属。
- 一个公司同一客户只有一个当前负责人。并发分配只有一个成功；相同分配重试幂等，已分配给他人的记录拒绝覆盖。本轮不添加转派功能。
- 各公司的取得、分配、沟通与额度独立。公共池仅保留现有公开事实，不加入公司私有沟通事实。
- 员工只能查询自己的客户，不能读取公司待分配列表、他人客户、搜索任务、平台来源诊断或修改额度。HTTP 与服务门面均校验当前身份；后台交付仍进入公司待分配池。

## 客户跟进

公司取得记录必须能进入客户工作台；管理员批量分配，员工看到自己客户及联系方式验证/自动跟进状态。采用现有 ProspectAccount、员工归属锁、联系人验证和 Outreach Campaign 边界接通后续动作，不能再建立一套不相连的 CRM。

选择客户后的自动跟进只能使用已确认的开发边界及已验证联系方式；缺少验证、已批准任务或邮箱配置时显示具体未就绪原因，不能把公开邮箱伪装成已验证。员工仅能对自己客户的跟进进行启动/停止或人工接管，不得修改公司授权边界或给自己分配客户。首次开发任务确认仍由企业管理员人工完成。价格、交期等承诺沿用原审批链。

本次验证不向真实客户发邮件，不伪造政策/批准/联系人验证，不增加模型配额或进行额外付费采集。

## 界面

日常主入口收敛为：找客户（仅管理员）、我的客户、消息、产品资料；管理员另有分配和必要的企业配置入口。开发任务并入客户跟进，需求证据和商机保留在相关客户详情/跟进操作中，不再作为并列主入口。供应卡、寻源、成本报价、运行记录、恢复工具等移出日常导航，数据和可追溯性保留。平台数据来源管理保持在 xue 控制台，不能把各公司供应商业务记录变成跨企业平台公池。

权限加载失败时界面默认不显示管理员操作。员工深链仍由后端拒绝越权；隐藏菜单不能代替权限。

## 验收

服务与 HTTP 越权测试；迁移保留旧归属并支持待分配记录；真实 PostgreSQL 并发分配、配额、公司隔离测试；前端身份切换/失败关闭、待分配和我的客户、批量选择/分配/跟进状态；结构检查和生产构建；升级服务器后用 jslt 真实 UI 验证，若会话过期由用户登录。无法由现有配置完成的自动发信明确显示未就绪，测试证据与实际线上能力分开记录。
