# Web 优先收口：交付范围与验收设计

日期：2026-09-05。状态：用户在规划后确认执行，现于 `codex/web-core-completion` 隔离工作树按批次实现。本轮仍不包含合并、部署或真实外部调用；完成状态以实施计划和同版本验收证据为准。

## 一、目标与使用场景

先交付一个可在浏览器中完整操作、可以重复验收的 TradeOS Web 核心版本。老板能发起并确认研究/触达提案，系统经现有工作流推进，客户回复形成带原始证据的已验证需求，授权员工接管；现有寻源、成本、报价和审批工作台继续可用。

首个里程碑按“本机浏览器、隔离测试数据库、受控外部端口”规划。部署位置已经向用户询问；在获得不同选择前，服务器和多人共享使用不作为本机验收的前提。这个假设不等于已有服务器部署授权。

两个完成口径独立记录：

- **Web 核心受控验收**：真实业务代码、数据库、工作流、API 与浏览器组成完整链，模型/邮箱/搜索等外部端口受控；无需真实客户与供应商。
- **多人部署就绪**：在前者基础上，另完成真实身份认证、会话撤销、部署运维和明确授权的来源验证。开发身份头不能用作多人登录系统。

## 三、方案与取舍

采用按业务链交付的方案：先固定版本和运行边界，再补 Agent 通用能力与启动组合，接通回复到接管，完善 Web 工作台，最后做同一版本的完整验收。

另外两种方案不采用：

- 先逐页美化再接后台：会在身份、权限、状态与异步恢复尚未确定时增加前端返工。
- 把所有 Phase 2 增强一起完成后测试：联系人多源、预算自适应和培养执行依赖额外策略/数据，会拉长核心 Web 的交付周期。

开发时每个批次做有针对性的模块和接口测试；集中端到端验收放在最后。真实客户运营仍单独安排。

## 四、本轮范围

### 4.1 必须完成

1. 单一可复现基线、运行模式和命令入口。
2. 通用技能注册/选择、上下文裁剪、权限工具交集、输入输出护栏。
3. API 与必要 Worker 的完整依赖装配、健康状态、正常停止和重启恢复。
4. 邮件正文受控读取、原文归档、入站关联、分类、已验证需求和人工接管。
5. boss / manager / sales 等现有角色的服务层范围与 Web 操作权限。
6. 关键页面的加载、空数据、无权限、局部错误、过期、暂停和未知执行结果状态。
7. 已有寻源、成本报价、独立审批和 PDF 交付链的跨页面回归。
8. Run 与人工接管的进度/等待/成本输入记录，以及可重复的集中验收。
9. 桌面扩展契约文档与 Web 独立运行边界。

### 4.2 暂缓

Tauri 程序、安装包、自动更新、Keychain 原生实现、目录监听、原生通知、本地浏览器接管；多租户产品开关、计费、钱包、WhatsApp、Temporal、图数据库、多模型路由；联系人多源瀑布、70/30 自适应分配、队列自动反压、Catalog 培养消费者、自动采购。

本轮修复既有寻源/报价功能，不扩展成真实供应商自动谈判。Catalog 页面必须如实显示 queued；既有未处理事件不得伪装为 delivered。下游恢复与消费属于后续独立交付。

## 五、架构边界

保持 `apps → workflows / agent_runtime → domains → shared`。域间不直接导入，业务规则仍归各域；跨域协作复用公开服务与事件。

### 5.1 执行归属

- 持久业务流程以已有 PostgreSQL 工作流为唯一状态来源，scheduler 负责推进。
- Agent 能力在确定步骤中执行；Manager 不变成长期循环的流程编排器。
- 只有实际需要通用 Agent Job 或浏览器作业时才启用相应 Worker；不得为“启动全部进程”复制第二套队列、租约和状态机。
- `apps/composition_support/AGENTS.md` 当前只允许报价机械装配，不把它直接扩为全系统容器。进程入口分别组合下层依赖；若确需公共组合代码，先有 ADR 并同步就近规则，禁止进程互导。
- 新入站能力优先由现有 scheduler 驱动的工作流步骤接入；如实际要求独立邮件入站进程，先以独立子规格和 ADR 说明隔离必要性，不复用只读反馈 worker 去执行正文落库或发送。

### 5.2 外部动作与受控模式

新邮箱正文读取只通过 Tool Gateway 的 manifest + check + handler 插件，不修改核心管线增加 tool_id 分支。Connector 负责协议与惰性取密钥，业务调用方只拿窄数据端口。

受控模式默认没有公网与真实凭证依赖，只替换外部 transport / model / identity 测试端口。不能替换关键领域规则、真实 PostgreSQL、Outbox、scheduler 锁、API 权限与浏览器请求。

受控历史发送记录必须通过现有受控发送公开路径产生；禁止直接插入 SENT、ValidatedNeed、Opportunity 或审批通过行来冒充完整业务链。

### 5.3 上下文与技能

- 工具许可取“技能允许 ∩ 用户允许 ∩ 当前运行策略允许”，再扣除显式禁用项；Gateway 继续独立判权。
- 身份与数据范围从受信员工/组织公开服务确定；`UserId` 到 `EmployeeId` 使用明确映射，禁止同字符串直接当作身份验证。
- 只载入当前任务需要的字段，邮件地址、原始 Cookie、对象键与凭证不得进入模型上下文。
- 必需权限/审批/禁用规则不可被 token 截断丢掉；历史资料先按预算裁剪并记录原因。现有通用优先级注释需与此规则对齐并补兼容测试。
- 技能按精确 trigger 选择并锁定版本；manifest 错误、重复冲突、非法路径、空 eval 引用均拒绝。加载技能不产生业务效果。

### 5.4 邮件入站与需求证据

正文先进入 RawArtifactStore，然后调用现有 `ConversationService.ingest_inbound`，由同事务发布 `InboundMessageStored`，scheduler 再启动回复流程。

严格处理同消息重放、缺失 Message-ID、错误 tenant、未知出站关联、自动回复、退订、投递反馈、超大内容和凭证标记；不能通过猜测 sender/domain 或弱关联认定客户表达。无法安全关联的内容进入有权限的待核对视图，不提升为已验证需求。

正文必须先经输入护栏再到模型；字段逐项带消息来源。回复分类结果事件 `ReplyReceived` 不可用于触发分类本身。

### 5.5 Web 身份与协作

本机受控入口只绑定 loopback；角色切换只操作隔离的受控身份，明确标注测试模式。共享部署禁止 dev 身份头。

多人版使用后端验证的认证主体建立会话，并映射为现有员工；角色、tenant、负责人由服务端推导。会话撤销、员工停用、跨角色缓存清空与 CSRF/请求来源约束都列为上线门禁。认证服务选型作为多人部署子项目的输入，不在本机批次内新造密码系统。

收件箱列表、详情、分类纠正、证据查看和附件下载必须使用一致的员工范围，不能只在 Vue 里隐藏按钮。manager 范围先遵守现有直属员工定义，不自行扩成任意下级团队。

## 六、桌面扩展契约

| 未来本地能力 | 现在保留的接入边界 | Web 当前行为 |
| --- | --- | --- |
| 文件选择/目录监听 | 复用有权限的上传与 Artifact 引用流程；监听器只产生待处理输入 | 手动上传可独立使用 |
| 本地凭证存储 | 受信 SecretResolver 的引用解析契约 | 运行环境的受信解析器负责，不向 API/模型返回密钥 |
| 原生通知 | Notification Adapter Protocol | 使用已实现的站内通道 |
| 本地浏览器/人工接管 | 既有 Browser Worker / Connector 边界，显式租户、账号与 Run 归属 | 核心 Web 操作不依赖用户桌面浏览器登录态 |
| 客户端能力发现 | 后端安全能力投影可区分 available / unavailable；未来客户端只能报告设备能力，不能授予权限 | 未实现能力不展示可执行入口 |

本轮保留文档和已有 Protocol 的兼容要求，不创建 `apps/desktop-tauri`、空 IPC 接口或虚假的桌面连接状态。

## 八、成本、指标与完成判定

记录 Signal → Hypothesis → Validated Need → Trade Opportunity 各阶段的唯一实体数和关联 Run；保留模型 token、来源调用/预算、人工接管等待时间和可核实的人工处理时长。

金额由确定性 Decimal 代码按显式费率/币种/有效时间计算。费用或工时缺失时标记未知，不作为零成本；没有可归因成本时不显示“每个合格贸易机会成本”的确定值。测试数据形成的指标不解释为真实业务效果。

核心完成必须满足 A1–A10、相关模块测试、单次同版本全量后端与 Web 验收，并交付运行与恢复说明。服务器共享使用另需真实认证与部署门禁；桌面端、商业数据源和真实成交不计入本轮核心完成条件。
