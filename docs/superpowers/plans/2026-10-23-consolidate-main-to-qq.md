# 主环境数据迁入 QQ 升级代码并统一入口

## Goal

按用户 2026-10-23 最新指令，只运行升级后的 QQ 代码，使用原主环境的企业数据、资料和配置；原域名继续使用。旧主环境只保留可恢复备份，开发源码完整保留。QQ 原测试记录不进入最终运行数据库。真实邮件测试仍关闭。

## Architecture

将主环境一致性冷备恢复到 QQ 目录下的新 profile，保留原主环境 tenant、业务 ID、对象 key、账号和模型绑定，分配新存储 owner。先使用旧主代码恢复 0078 数据库，再使用 QQ 当前代码升级到 0102。复制并重绑定私有目录，不把不同租户的数据库直接合并。验证后切换 QQ 服务和 nginx，停用旧主环境及其自动启动入口。

## Tech Stack

Python 3.12、PostgreSQL、MinIO、systemd、nginx、现有 PilotProfile 冷备/恢复/迁移命令。

## Global Constraints

- 工作仅针对服务器 `/srv/tradeos`；不使用 T7。
- `/srv/tradeos/development/TradeOS` 的代码和未提交内容不修改。
- 私有数据和凭证只在受信服务器进程内复制、校验；不进入日志、Git 或模型上下文。
- 主环境和 QQ 先完整备份，备份含源码、前端构建、数据库、对象、私有文件和部署配置。
- 复制资料保持原始文件字节不变；只修改有明确语义的部署路径字段。不得重写业务文档正文。
- 邮件自动发送、回复监听、历史测试 worker 关闭，不进行真实收发。
- 只有新环境数据核对和 HTTP 检查通过，才切换域名；仅确认精确归属的旧容器可以清理。
- 迁移前后核对每张原表的原字段内容；会话撤销、schema 变更、明确迁移变更单独记录。
- 原 Tavily 配置保留为可选获客源，不恢复为默认检索后端；不擅自开启付费搜索。

## Review Focus

冷备一致性、实际恢复可用性；旧资源与新资源身份不混用；平台和企业数据库角色绑定；所有私有路径脱离旧主目录；历史邮件不被重发；nginx Origin/Host 和端口一致；旧服务不会通过 timer/path/依赖复活；开发源码未改；验证结果不夸大为真实获客或真实邮箱验证。

- 停止主环境、QQ 和相关 worker，暂停公共入口写入。

- Expected: 两份数据库/对象冷备校验成功；原主私有文件、源码可核对；开发 checkout 指纹不变。

### Task 3: complete — 恢复并重绑定

- 在 `/srv/tradeos/acceptance/qq-20261019/main-data-20261023` 建新 profile，使用旧主源码恢复。

- Expected: 原主业务数据完整保留，新 schema=0102，QQ 测试数据未混入。

### Task 4: complete — 发布与清理旧运行入口
