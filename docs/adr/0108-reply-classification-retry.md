# ADR0108：未派发分类失败的一次人工恢复

状态：用户已于2026-10-19批准设计，实施与隔离验收中。

## 背景
原入站回信已归档，模型准备阶段失败；原规范 reply_qualification Run 永久失败。人工纠正只适用于已有分类，不能替代真实识别或触发业务动作。重启已停止的 QQ 试验会破坏原预算与失败事实。

## 决策
普通当前负责人或老板在消息详情显式点击“重新识别”。API 只接收消息 ID、空命令和原 Idempotency-Key，当前权限仍由会话域规则裁决。新 reply_classification_retries 表绑定 tenant/message/原 Run/原 invocation/原失败 step/操作者与用户/owner及锁时间/原件与出站/模型配置版本，五分钟有效。

仅唯一 rejected、dispatched_at=null、sequence=0 且原 QQ provider_requests=0、没有 pending provider、尚无分类的失败可以恢复。新恢复事务按 step→run 的原锁序，再锁当前归属与员工和配置指针；旧失败 step、invocation、Run.last_error、QQ试验保持。新增同一 Run 的 pending classify step，恢复授权本身是追加审计；同消息仅一条授权、同租户键唯一。

seq=1 必须由该授权产生，逐次重验当前操作者和原分类者、原关联与配置。原 seq=0 不放宽；历史调用读取包含所有序号，任何未授权身份都拒绝。只有持久授权存在时，原件读取与分类提交显式选择恢复门禁，不能由旧试验错误回退而自动选择。

原 model.generate Gateway、全局调用次数及并发继续生效。恢复另外最多一次分类、四轮 provider、累计32768输入字节、512输出token、60秒，受原更严限制约束。每轮先持久预留再调用，未知不退款、不自动重试。分类与恢复classified状态同一事务；进程崩溃重放只能复用已保存的真实分类，不能再发模型请求。

分类通过原校验、证据与事件链，再沿原幂等动作生成工作项和老板通知。私有测试既有分支不晋升 Need/Opportunity、不发 WhatsApp、不产生报价。UI明确人工恢复与原失败，未知结果只读刷新，显式使用原请求才可重新提交同键。

## 部署与回退
0081采用既有固定企业角色 RLS；分文件ORM显式注册到隔离自检。迁移空库升级/降级/升级验证；有恢复记录拒绝删除证据式降级。仅部署隔离验收实例；生产不切换。原邮箱/模型额度不调整。

## 运行组合
恢复提交守卫由一次性绑定槽接入原 canonical ConversationService，不替换实例。QQ配置增加显式 recovery_only，不能与新试验配置并存；保持原件存储和回复处理端口，关闭 InboundDriver 的邮箱扫描，不运行试验启动采集。该模式的消息访问和模型身份必须有恢复授权，不能推进其他未授权分类。停止试验的历史行保持不变。

## 0082 范围纠正

五分钟是本次助手测试自加的期限，用户明确不能作为正式规则。新恢复请求不限制排队等待；原测试 expires_at 保持不可变。只为已到期且确定零开始的旧测试记录追加一次不可变续办凭据；普通请求不提供续办入口。模型真正开始仍受60秒/一次分类/原全局额度约束，权限与配置在执行前现查。
