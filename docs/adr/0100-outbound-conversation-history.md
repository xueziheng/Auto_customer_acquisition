# ADR0100：已发送邮件归档与会话展示

状态：实现并验收后发布。

## 问题

Outreach Attempt 已记录 SMTP 接受，但 Conversations 只写入站消息，导致用户在消息页看不到已发送邮件。
关闭入站处理时，原件读取服务也未装配；仅增加一个 UI 标签无法修复缺失的业务记录。

## 决策

在现有 email.send handler 的发送及对账返回确认之后，通过独立归档端口保存本次提交内容，
调用 Conversations 公共 record_outbound。使用既有 tenant + account + email 会话和外部消息 ID 幂等约束；
仅推进 last_outbound_at，不发布入站事件，不改变回复状态、分类、自动跟进、审批或六阶段管线。
API 手动发送和已配置入站对象端口的 scheduler 发送均接入相同适配器。

正文与主题只保存在不可变 Artifact Store，数据库和工具审计只记录 ID、时间及安全结果。
副本明确标记 submitted-content，保存实际提交的收发地址、主题、正文与稳定关联头，
不包含随机退订能力 URL，不冒充服务商处理后的收件原文。历史回填必须核对 SENT、精确 provider receipt
和原发送材料；回填不得调用 SMTP 或伪造入站、客户回复、采购意向。

SMTP 接受后归档失败必须保持 reconciliation_required；恢复只调用原有对账分支，不得再次发送。
同一绑定重复归档只返回原消息，内容变化拒绝。既有无对象存储的受控组合保持兼容；生产配置对象存储。

消息页展示已发/入站、等待回复、时间、收发地址、主题和纯文本正文。内容读取继续走原 inbox evidence
Gateway，读取前后核验当前员工与客户归属、租户和对象完整性；响应 no-store，HTML 不执行。
读取能力独立于回复抓取开关，不导入用户邮箱中无关的历史通信。

## 验证

真实隔离 PostgreSQL + MinIO + 受控邮件传输验证发送→归档→会话→HTTP；覆盖无入站配置可读、
非当前负责人拒绝、错误 receipt/跨企业拒绝、重放幂等与异内容冲突。发送处理器验证归档失败只对账；
Conversations 验证无伪造回复事件与时间不回退；浏览器组件验证纯文本和等待回复展示。
真实部署与 UI 证据记录在本次验收文档中；旧 QQ 回信尚未关联不属于本次修复完成范围。
