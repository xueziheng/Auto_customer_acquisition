# ADR 0101：人工确认的两封 QQ 历史回复恢复

2026-10-16。用户明确要求恢复本人两个测试邮箱对 Q01 的两封回复，并查看收发全文。

QQ 回信引用 QQ 改写的 Message-ID，现有发送原件没有该别名，自动精确关联无法证明对应。
本次按用户明确确认恢复，不能将同主题匹配宣称为自动验证成功。

一次性运维 Gateway 工具绑定原 tenant、当前 owner、本人邮箱、私有测试授权和唯一 SENT attempt。
只查询原发送日，最多读取 20 个头；只读完整匹配双方、无抄送、唯一主题、发送后 30 分钟内的
恰好两封正文。两封分别包含用户确认的回复原话和完整原信引用，编号唯一且引用相同 QQ 编号。
匹配任何一项失败整批停止。原 MIME 不改写，人工关联依据、操作者和原 QQ 编号保存在私有恢复清单，
内容只通过原件存储和当前权限验证后的会话接口读取。Connector 不直接写业务表。

恢复调用原 conversations.ingest_inbound，保留原时间与原始外部编号，以原 SENT 确定性编号建立
人工确认的关联；幂等检查不变。恢复前须确保原入站事件消费者可用，不跳过事件或伪造分类。
不重置 blocked 游标，不修改自动匹配规则，不发送新邮件、不导入其他历史正文。

会话摘要选择实际最新消息，详情最新在前，明确显示发送/收到时间；HTML 邮件仅提取安全纯文字，
不执行 HTML 或加载远程图片。历史补入时间不替代邮件自身时间。

同日补充：用户继续要求完整收发内容，已在本人 QQ 界面观察到 Q02 的新回复“我想了解更多”。
按独立 Q02 SENT attempt 和原提交正文恢复这一封，明确时间窗为发送后 1 小时。
每批由受信清单指定 1–2 条确认原话与时间窗（默认30分钟、最多1小时），实际数量必须完全一致；
Q01 的两封和 Q02 的一封分别审计，不将新回复混作旧信回复。人工授权来源记录为本次用户请求，
不得冒充公司老板账号进行了网页审批；受托模型分类身份与人工授权来源是不同事实。
