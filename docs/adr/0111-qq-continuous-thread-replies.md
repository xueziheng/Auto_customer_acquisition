# ADR 0111：持续 QQ 收信识别同会话的连续回复

2026-10-20 现场发现：第二封回复的 In-Reply-To 指向上一封已收回信，
References 保留已验证的 F 发信别名。仅查询原始 In-Reply-To 会把该 UID
当作无关邮件推进游标，导致漏收。

持续模式使用两个独立、有界的单邮件头查询：In-Reply-To 和 References。
不使用 QQ 不兼容的组合条件，不扫描全邮箱；候选取并集并保持原 UID 页上限。
只有来源仍有效的唯一发信别名、精确邮箱对、合法且不重复的 References 链
以及末端匹配即时父邮件编号时，才认可连续回复。试验模式和非持续模式维持原策略。
当前权限、真实已发事实、完整 MIME 校验和原件归档仍在正文处理前后核验。
归档保留原始邮件头；解析后的会话关联使用原 canonical 发信编号。

已越过的单个 UID 由显式补收 reader 经原 Gateway/原件归档/整页事务重收，
要求 UIDVALIDITY 不变、UID 已在保存进度以内、当前范围仍有效且恰好一封。
临时读取范围不写入 cursor；返回页的起止 cursor 均为当前保存值，
receipt/Message/outbox 的原幂等规则保持生效。禁止无界补扫或回退进度。
