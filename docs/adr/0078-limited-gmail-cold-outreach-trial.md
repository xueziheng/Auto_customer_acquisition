# ADR 0078：项目 Gmail 的限量冷开发试验

- 状态：已接受（仅限操作者确认的本机首轮试验）
- 日期：2026-10-03
- 影响：发件身份认证门禁的单身份试验策略；不改变其他身份的默认规则

## 背景

首轮目标是以现有项目专用 Gmail 验证“肯尼亚公开研究 → 已验证联系人 → 首封邮件 → 回复 → 人工接管”。主业务邮箱不使用 `gmail.com`。现有 DNS 检查把 `_dmarc.gmail.com` 的 `p=none` 判为 `POLICY_UNSAFE`；它不能被记录成 DMARC 通过。原发件身份规则要求 SPF、DKIM、DMARC 全部通过，且冷开发与主业务域隔离。

## 决策

只允许这一个经操作者确认、与主业务邮箱隔离的项目 Gmail，在首轮最多十封、每天最多三封、只发第一封的试验中使用显式例外。认证事实原样保存为 `POLICY_UNSAFE`，不得伪造 DNS 通过或修改通用分类器。例外必须绑定租户、精确地址、Campaign 版本和持久的试验授权；任何字段不匹配、身份变更、额度用尽、信誉限制、退订不可用或授权撤销，都拒绝新发。

试验仍需显式启动预热，并经过联系人可达性、国家政策、Playbook、抑制名单、Campaign 批准、发件额度、发送幂等、真实 HTTPS 退订和 Gmail 投递反馈门禁。首位陌生客户的证据与邮件正文须由老板确认；之后仅在同一批准边界内自动发送。不得将此例外推广至公司主业务域或其他免费邮箱。

## 理由与代价

直接购买独立域名并完成 DMARC 强制策略更符合常规冷开发信誉要求，但本轮用户明确选择免费、低量、先验收现有源码。严格隔离和十封硬上限降低影响范围，不能消除 Gmail 信誉、收件箱判垃圾邮件、账号限制或 `p=none` 的风险。技术验收不等于真实客户转化。

## 放弃的选项

- 将 `p=none` 记为“通过”：会篡改 DNS 事实，禁止。
- 绕开发件身份或 Gateway 直接调用 Gmail：会失去额度、抑制、审批与幂等，禁止。
- 此次立即购买专用域：可作为正式运营方案，但不是本次免费试验的前置条件。

## 重新审视

十封上限触达、账号信誉异常、退订入口不稳定、计划扩大到其他身份或正式持续运营时，试验暂停；需重新评估专用域、认证与预热，不能自动延长本例外。
