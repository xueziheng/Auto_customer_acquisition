# ADR 0114：普通询盘的模型跟进

2026-10-21 用户要求修复老板第四项，并转达自动回复需要复用现有 Codex CLI / DeepSeek 的要求。
旧 TEST-04 的固定正文路径不足以证明普通新询盘自动跟进。0113 保持原指纹和事实，本路径不延长旧单封授权。

本次沿现有 Codex 公司模型和 model.generate Gateway 新增 business_mail_followup 能力。模型只理解本次客户纯文本、逐字提取产品/用途/数量并选择最多两个缺项；确定性英文模板防止未审批商业承诺。模型没有发信工具或凭证，发送仍经 email.business.reply 的 HIGH 六阶段及真实身份额度预留。未知模型结果和未知投递不自动重试。

授权采用当前 owner、邮箱、连接与发件身份版本、起止时间、配置收件范围；代码不包含特定主题、型号或 message ID。首次恢复的旧邮件须单独明确列出，之后的新询盘不需逐封改代码/配置。当前仅用于受控内部验收，最长24小时；不是共享生产或全量客户营销开启。

复用0086追加历史保存模型claim、逐字来源、提案、草稿、发送引用和人工处理，不引入第二套状态库。claim先提交再模型派发，结果缺失需人工核对；单实例Postgres锁与稳定原信发送键共同防止重启重复。发信范围和模型权限逐次重核当前事实，不直接更新业务表。

普通新询盘只认完整原件和非机器人/列表直接邮件；真实回信以 From/To/References 关联。人工状态不得被自动完成。测试数据不创建ValidatedNeed或Opportunity，供应规格/MOQ等没有来源则等待负责人核实。

2026-10-21真实回信验收补充：分类pending/classifying时不创建跟进模型claim；已匹配真实线程的model review可提取供负责人核对，人工review、other及failed不借此放开。授权端重核原线程和同版本来源。
模型曾把明确标注test data的本次补充整个返回review空字段，该真实结果完整保留。提示补充“模拟字段仍需逐字提取并标明测试、保留约数限定”；契约样本验证来源与不晋升边界，不冒充真实模型评测。后续用新询盘验证首次自动链，不重置或删除旧run。
