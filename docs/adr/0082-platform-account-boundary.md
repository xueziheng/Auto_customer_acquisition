# ADR 0082：四账号与独立平台只读入口

日期：2026-10-08。状态：按用户明确要求实施。

## 背景与决定
用户要求取消其余登录账号，实际启用 xue、jslt、qihao、qikai。前一设计仅有文档，线上仍只有 test_admin。本批以四账号可登录、权限真实分离、旧账号不可再用为交付目标。

xue 位于独立平台控制 tenant，使用独立 PostgreSQL 受限角色、会话 Cookie 和平台授权记录；兼容认证所需的 Employee 行仅存在控制租户，不属于 JSLT。viewer 角色本身不授予平台权限，每次读取还须验证平台授权、当前账号和用户映射。平台子应用从零只注册登录、会话、退出、企业使用概况，不装配业务写接口、模型或 worker。

JSLT 复用现有 tenant，jslt 底层映射 boss，qihao/qikai 映射 sales 并关联 jslt。界面称企业管理员和员工；原业务权限、独立审批与负责人检查不放宽。只停用旧账号、撤销会话并停用旧 Employee，保留历史引用；有客户归属需要交接时先检查，不硬删除业务数据。

平台概况逐企业使用固定绑定的 reader、明确 tenant 过滤与只读数据库事务；记录平台查看审计。控制身份不取得企业数据库直连能力；企业统计连接是服务器持有的运行连接，不能声称该数据库角色本身只有 SELECT。未授权企业不注册，无读源或失败显示未知。平台查看数据不进入 JSLT AI 上下文。

入口为 /platform（平台）与 /（企业），均在 trade.jslingte.com。平台 API /api/platform 先于业务 /api 挂载，Cookie 名称和路径独立，切入口整页导航。父应用显式启动双方 lifespan，任一验证失败关闭，退出清理连接池。

## 本批边界
本批实现四个指定账号与平台企业概况。自助企业开户、邀请、计费、平台查看业务明细及限时查看会话仍是独立后续功能；页面不出现未接通的按钮。九条全局硬边界保持不变。

旧设计中“保留 test_admin”被用户本次“取消所有旧账号”覆盖。密码按用户本次选择交付，凭证不进入 Git、日志或模型输出。代码和测试只在阿里云/CI，原电脑 WSL2 不动；不新增业务备份，不发送邮件，不调用付费模型。

## 测试密码例外
沿用用户已明确指定的六位测试密码时，仅可信四账号初始化显式开启 test_password。摘要采用相同 scrypt 参数并携带 scrypt-test 策略标记，验证最低六字符；通用开户/重置仍要求十字符。HTTP 不接受该标记，不能通过登录请求自行放宽策略。使用强密码重新设置时恢复普通摘要格式。此配置只用于用户当前四账号测试，不适用于正式企业推广。
