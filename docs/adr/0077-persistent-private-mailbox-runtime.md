# ADR 0077：本人邮箱的持久运行与邮箱登录

状态：已接受。日期：2026-09-27。

## 背景

用户需要在本机持续查看已授权 Gmail 的全部收件、已发送和历史邮件，同一个人可以拥有多个邮箱。
ADR0075 的镜像、只读 Gateway、归属隔离和页面已实现，但 worker 为获取数据库和指纹配置而强依赖
完整 PilotConfig。完整配置要求贸易评分和交接政策；不能为了查看本人邮箱而填入合成商业政策或测试员工。
原登录名只接受 64 字符以内的短用户名，也无法直接用邮箱地址登录。

## 决策

1. 在既有 API 与 email_feedback_worker 进程内增加窄运行入口，不新增业务域或第八个进程。
   私有 MailboxConfig 仅保存独立持久 PostgreSQL、固定本机端口、技术秘密及明确的邮箱绑定。
   保留完整 PilotConfig 的商业政策要求，不注入空对象伪装完整业务已配置。
2. API 复用原会话认证、CSRF、员工事实查询和 MailboxService。只提供身份和本人邮箱依赖；其他业务仍失败关闭。
   Web 复用 `/inbox/mailbox`。页面显示本地镜像状态，只有历史与增量追平后才能声称同步完成。
3. 登录账号与邮箱绑定分离。支持规范化为小写的 ASCII 邮箱登录，保留旧用户名、邮箱的点号与加号。
   一个员工可绑定多个已授权邮箱；同租户同邮箱不能转移给另一员工。邮箱授权文件彼此独立。
4. 通过可信本机 TTY 创建真实 viewer 账号或验证既有账号后追加绑定，密码不经过聊天、参数、日志或模型。
   迁移0069扩展登录字段至254字符；保留所有旧账号和会话，有邮箱登录数据时拒绝不兼容降级。
5. 显式 init/migrate 负责数据库迁移；应用和受管后台启动只检查 schema，不自动升级。
   supervisor 管理 API 与各绑定的只读 worker，macOS LaunchAgent 负责登录后启动及进程恢复。
   凭证只以私有配置路径引用，PostgreSQL 与 Web 均绑定127.0.0.1，停止不删除持久数据。

## 边界与后果

镜像不调用模型、不发送邮件、不修改 Gmail 标签，也不生成贸易机会或客户记录。每个邮箱继续使用
ADR0075 的前后锁心跳、Gateway 审计和整页原子检查点。新配置不授权读取其他邮箱；账号本人仍需分别完成 OAuth。

本机关闭、休眠或 Docker 停止期间不能实时同步，恢复运行后从检查点补齐。OAuth 到期仍需本人重新授权。
这不是多人公网部署或网页登录 Google 的实现；多人共享部署仍须独立设计身份注册、回调和组织管理。

## 验证

覆盖邮箱登录兼容与归一化、迁移往返及拒绝破坏性降级、真实数据库本人/租户隔离、多绑定归属、
窄 API 的登录与 CSRF、其他业务失败关闭、后台精准资源管理与恢复、页面同步刷新和旧请求隔离。
真实邮箱全量及增量验收单独记录，不以受控测试替代。
