# ADR 0083：企业资料整理与 Obsidian 文档投影

日期：2026-10-08。状态：按用户明确要求实施，沿用 ADR0081 企业隔离和 ADR0082 三身份。

## 背景与目标

用户要求每家企业上传自己的公司、产品和规格资料，由服务器上的 Codex CLI（DeepSeek）
分析后存入企业 Obsidian 资料库，所有用户仅使用网页。现有 workspace.py 只有临时只读快照，
员工 work_intake 是本人业务记录，不是企业资料；本次建立独立企业资料入口，不改写旧语义。

## 决策

- PostgreSQL 保存不可变原件引用、资料记录、任务、分析版本、完整来源与确认状态；
  原件保留现有 Artifact Store。Obsidian vault 是企业专属 Markdown 投影，不是权限数据库。
- 产品域新增企业资料服务与独立 DTO/仓储。全员共享本企业资料、可以上传；在职企业管理员
  确认精确版本。上传不会直接创建正式 Product、客户 Quote、发送或获客任务。
- 上传与排队同事务，同企业原件去重。后台单例领取有租约与 fencing 的任务；
  处理中的未知结果不得自动再次调用模型。人工重试产生新任务并明示可能重新调用。
- 原件类型新增 TEXT（TXT/Markdown）；CSV继续沿用 EXCEL。本次处理UTF-8文本、
  PDF、DOCX、XLSX、CSV及PNG/JPEG/WebP。按用户补充要求，扫描或含图PDF页在离线沙箱内
  渲染后，连同独立产品图片交给当前DeepSeek视觉接口。语音不在此范围。
  图片真解码、去元数据并限制像素与尺寸；最多10图、每图8MiB、总16MiB，超限拒绝而非裁剪。
  保留图像索引到原PDF页的映射；解析/转录均是派生内容，不能代替不可变原件。
- shared ModelCapability 增加 knowledge_ingest。复用 model.generate 的授权、持久调用额度、
  幂等与用量账本，不修改 Tool Gateway 核心管线。ModelRequest增加独立typed图像附件，
  当前max_input_bytes继续限制prompt与JSON正文，图像另受上述独立硬上限限制。无图指纹和请求
  保持兼容；有图指纹包含有序MIME/hash/长度，账本不落bytes/base64。
- 新 Codex provider 确实运行已安装 CLI，使用每任务只读快照、临时 CODEX_HOME、
  --ephemeral、--ignore-rules 和 bwrap 文件/进程/网络命名空间。只开放固定结构化分析，
  不开放 shell、任意工具、共享配置或旧共享 vault。
- DeepSeek密钥仅留在父连接器。隔离进程经私有 Unix socket 转交本次固定请求，
  一次 Gateway 预留最多对应一次真实 Provider 请求；CLI不能更改租户、模型、正文、
  限额或重复执行。输出与实际模型完成结果绑定，用量来自真实 Provider。
- 模型输出严格区分逐字事实摘录与有来源的推断。事实值须在引文内、引文须在原文内；
  来源、模型、提取时间由服务器记录，确认人/时间由当前授权事务记录。禁止模型概率、
  自动承诺或最终金额计算。视觉来源显式标为vision_transcription；没有文字的产品照片只能
  形成附图像页号的推断，不能编造规格事实。转录后的逐字校验仅证明输出内部一致，仍须核对原图。
- 可信代码确定性生成 Markdown。模型不能决定持久路径、写生产库或 vault。
  每企业独立 vault，不对 CLI 暴露父目录。文档同步有独立状态；失败只重试文件同步，
  不能为了同步再次调用模型。版本/来源保留，拒绝软硬链接与路径穿越。
- 原权限契约不变：企业资料共享不开放旧产品内部成本/供应商视图。平台控制租户不进入
  企业资料处理；xue的企业概览不赋予JSLT跨企业读取权。

## 验收与限制

验证上传幂等、来源/推断分离、确认权限、重启/租约恢复、未知调用不自动重试、
撤权前后检查、同文件双企业隔离、恶意路径/压缩包/凭证输入、持久vault同步恢复、
真实CLI离线探测及少量合成资料真实DeepSeek链路。完整CI与部署证据分开报告。

目前部署仍是一个业务企业JSLT加独立平台控制租户；多企业开户不是本次功能。
本次不包含Obsidian桌面嵌入、Sync订阅、双向桌面编辑、本地大型OCR模型或自动获客/发送。

## 处理容量与部署验收

资料字符数和模型输入字节数不同，CLI 实际 JSON 封套在 Gateway 预留前按 UTF-8 计量，
超限提示拆分资料，不消耗调用次数。Provider 明确返回输出 token 上限截断时，不保存部分
转录或推测为完整资料，固定归类为容量超限。图像页数上限不是保证任意文字密度都能完整转录。

部署应为真实资料量设置模型输入、输出和超时上限，配置版本变化后重新完成模型连通验证；
保留每企业/员工的调用次数与并发限制。服务器只保留必要的服务与小规模真实流程验收，
类型检查、前端构建、完整数据库/浏览器回归由 GitHub Actions 执行，生成类型与构建产物
均可下载核验，生成契约与提交内容不一致仍会令 CI 失败。
