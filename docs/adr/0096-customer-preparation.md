# ADR 0096：本人客户公开资料与产品适配准备

- **日期**：2026-10-14
- **状态**：按用户已授权的客户资料准备切片实现；真实来源采集、法律依据、邮箱验证与发送须分别核验。

## 背景

公共候选分配桥接只创建账户与真实归属，刻意不猜客户类型、行业、法律依据、联系人或需求假设。
因此员工在已分配客户详情中仍可能缺少触达前置资料。已有 `resolve_account` 只合并来源引用，
不能把客户类型等缺项变成已确认事实；公开邮箱也不能当作已验证联系方式。

## 决策

新增独立资料准备契约、应用服务、HTTP router 与客户详情子组件。写入始终在当前
员工→取得记录→归属锁 guard 内，仅允许当前真实负责人；管理员查看他人客户不授予写入权限。

公开事实与员工推断为不同字段：公开原话、URL、观察时间、页面哈希及本企业真实网页快照引用
形成 Demand Signal；类别与员工适配理由形成有证据的 Need Hypothesis。沿用 Demand
网页快照 tenant/kind/hash 校验，不使用 employee_input 回避真实网页证据门禁，不晋升为 Validated Need。

Prospecting 增加 `fill_missing_account_profile`，在账户行锁内只补缺失的客户类型和行业，
保留人工确认的字段级 Provenance。同值复用首次记录，冲突拒绝而不覆盖；既有名称、国家、
域名、归属及来源引用不由该方法改写。资料、信号、假设、联系人和法律依据通过借用同一
数据库会话保存，任一步失败整体回滚。

邮箱可不填写，先完成公开资料与假设。填写邮箱必须提供 `LegalBasisInput`、实际持有的
评估/依据记录引用和明确人工确认；不默认 consent、existing_customer 或合法利益评估已完成。
本切片仅支持显式确认的法人企业公开职务邮箱，沿用联系方式指纹原子去重，新增 ContactPoint
一律为 UNVERIFIED。它不执行可达性验证、入组、发信、对客户报价或商业承诺。

重放复用原域服务的稳定身份：网页信号来源哈希、账户内活跃类别、联系方式指纹；
不新增数据库迁移或另一套联系人/假设仓储。HTTP 命令禁止客户端提交企业、操作者、负责人、
确认人及验证状态。前端通过生成的 OpenAPI 类型调用，换身份/403 清空资料和表单；
未知保存结果先只读核对，显式重试保留原命令，不自动重发。

## 代价与重新审视条件

来源采集不是资料准备接口的隐式副作用。没有本企业网页快照时无法保存，后续可通过
独立受控 Gateway 来源动作改善交互；不能给网页证据或联系人验证开后门。

原域没有法律评估登记库。当前只留操作人显式提交的依据引用，不宣称后端已核实评估记录内容
或完成法律评估；需要正式评估审批/撤销时，应新增受控公开服务并在消费时重新核验。

当前幂等按现有活跃事实去重，不是永久命令 receipt。若已拒绝的假设需要禁止原命令再次形成
新活跃假设，或准备动作需要完整命令历史与严格冲突语义，应加入独立 append-only receipt；
不能把原假设反复改成“客户需求已验证”。

## 验证

真实 PostgreSQL 覆盖当前身份/归属和租户拒绝、来源不匹配回滚、类型冲突拒绝、末端邮箱
失败整体回滚、自然重放/并发去重、邮箱保持未验证以及 HTTP 身份字段拒绝。
前端行为测试覆盖事实与推断请求、缺依据时不发送邮箱录入请求、服务器权限以及换身份后的迟到响应。
这些受控测试不证明真实网页采集、评估记录内容、联系人可达性或邮件投递。

## 已有候选原件复用

受信候选公开投影已有 `web_page` Provenance 时，前端只在 `source_id` 是规范 `art_` 原件编号、
`page_hash` 是小写64位SHA-256时自动填写来源凭证，减少人工抄录及重复外部读取。
不兼容或缺少来源时不补造编号；保留真实原件手动补充入口。自动填入不代表原件可用，
保存仍由 Demand 精确校验本企业的真实 Artifact ID、kind 与 hash。另一企业拥有同内容哈希的
原件也不能通过；类型/行业、信号和假设必须整体回滚。不存在新增网页采集 API、Gateway 工具或
隐藏 Provider 调用，员工点击保存仍为人工确认。
