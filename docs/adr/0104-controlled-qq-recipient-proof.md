# ADR 0104：自有 QQ 收件邮箱原件作为受控验收证据

日期：2026-10-19。范围：两个已明确授权的自有测试邮箱，独立验收实例。

## 已核实的问题

真实 A 邮件投递后保留了 X-TradeOS-Idempotency-V1，但 QQ 将 Message-ID 改写。
发件箱唯一客户端副本仍使用原编号；收件方原件的改写编号与真实回信引用一致。
现有 sender_sent 采集路径因此无法准备本次受控回信验收。

## 决策

新增明确来源 controlled_recipient_imap，保留 sender_sent 的原语义和 recipient_export 的诊断限制。
新工具 email.qq.delivery_alias.read 只能在原单副本 scheduler 的准备阶段通过 Gateway 执行。
配置须明确收件邮箱当前员工、用户、单个 INBOX UID、UIDVALIDITY 和本次用户授权引用；
该员工和用户必须是本次已授权的分类老板，避免引入第三个受托账号；
两个邮箱均沿现有受保护连接读取凭证，不从原始头推断身份，不借用发件方凭证。

只读取一次必要邮件头，不搜索，不读取正文，不 APPEND；核对唯一原 Message-ID、精确幂等标记、
双方地址、无抄送及原始字节哈希。原件经 Artifact Store 归档，只有真实成功工具调用可登记编号关联。
登记时核对专用工具、收件方 actor、发送 attempt、原件哈希和大小；来源与收件方 actor 进入原 trial scope，
历史 sender_sent scope 使用兼容默认值。手工导出、诊断文件和已有诊断调用均不能激活 trial。

授权检查同时验证发件方原资格和收件方当前员工/邮箱连接。恢复绑定同一配置指纹、原键和原件，
不更换失败 attempt 的预算。准备阶段沿原硬截止和资源清理；保守计入原一次会话、搜索和头预算，
即使单 UID 采集没有执行 SEARCH，也不扩大原总额度。

## 验收边界

真实试验需新发送尝试、全新 trial 与游标，用户在准备完成后发出新回复。A 邮件只用于诊断，
不得重放其历史回信冒充自动接收。自动发送保持关闭。
这不是通用客户邮箱方案：真实客户不会为系统提供收件邮箱授权码，本改动不能据此宣称生产自动回信全量可用。
