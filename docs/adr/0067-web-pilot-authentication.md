# ADR0067：本机 Web 内测的 Postgres 认证

- 状态：已接受，依据已批准的 Web 持久化内测设计及控制器接口裁定。
- 日期：2026-09-07
- 范围：单租户 loopback 内测；不提供公网身份平台、注册、邮件找回或默认账号。
- 编号：原计划 0028 已被占用，顺延至当前空闲 0067；迁移 head 为 0059，新增 0060。

## 决策

`shared.authentication` 定义冻结身份、会话和认证 Protocol。权限仍读取当前员工事实，不在账号表复制业务角色。`infra.authentication` 只绑定既有本租户活跃 Employee，业务员工创建由可信应用装配负责。所有账号、会话和限流记录均以 tenant_id 为复合键的一部分，账号→员工、会话→账号的复合外键拒绝跨租户关联。

密码使用固定参数标准库 scrypt：N=131072、r=8、p=1、dklen=32、随机16字节salt、maxmem=268435456。只接受15–128个Unicode字符且UTF-8不超过512字节，不截断或去空白。存储格式为固定参数加精确长度十六进制盐和摘要，解析不接受任意资源参数。全部服务哈希经进程级最多两个工作线程执行，取消等待不会提前释放尚在执行的工作槽。未知及停用账号使用相同成本的虚拟验证；错误输出固定，不含底层数据库异常。

会话 token 是32字节随机值的 URL-safe base64 无padding编码。数据库只保存编码后 token 的 SHA-256 摘要。CSRF 使用解码后的32字节 session token 为 HMAC-SHA256 密钥、固定上下文 `tradeos:csrf:v1` 派生，并以 URL-safe base64 无padding编码；同样只保存编码后材料的 SHA-256 摘要，校验用常量时间比较。该裁定解决“独立随机 CSRF 且只存摘要”无法在刷新后恢复 CSRF 的原设计矛盾；`get_session` 只读重建材料，不续期，不旋转，也不在 GET 写入。IssuedSession 的材料均为 SecretStr、repr=False 且默认序列化排除；可信 API 必须单独选择 Set-Cookie 与 CSRF 响应字段。

会话绝对有效期8小时，每次登录发行新值，账号最多五个活动会话，多出的旧会话按发行时间撤销。认证用单条联表查询检查当前启用状态、员工活跃、发行时user映射、账号版本、撤销与到期。不从客户端接收租户或角色。

## 事务与并发

登录先在独立事务更新租户尝试桶并提交，随后在认证事务取得租户 attempts 桶行锁，再取得账号行锁。重置、启停、创建与全租户撤销采用同一租户锁顺序；登录哈希在工作线程执行，但认证事务保持锁直至发行或失败计数提交。失败异常只在事务提交后抛出，因此不会回滚失败计数。所有时限使用数据库实际时钟。

已知账号最多5次失败/15分钟，未知用户名共享本租户一个15分钟失败桶；租户最多30次尝试/分钟。桶窗口到期后重置，拒绝状态保持计数上限，不因未知用户名增长记录数。账号成功登录清账号失败计数；重置密码也清失败计数，但不清租户尝试桶。

重置与启停同事务增加账号版本并撤销会话。`revoke_all(username=None)`在租户锁下撤销该租户全部会话，与发行线性化；撤销完成后新发起的正确密码登录仍合法。退出仅幂等撤销精确会话。提交后发起的认证不能接受旧会话；已被接纳的在途请求不承诺事务回滚。

账号创建可接收已开启事务的外部 AsyncSession，以便可信应用创建 Employee 和绑定账号原子提交。适配器只 flush，不接管外部提交/回滚；异常时调用方必须回滚。允许调用方先插入随机新ID、全新user_id的Employee再调用；未提交的新员工不可见且尚无账号，因此不会与已有登录的Employee锁冲突。调用方不得在调用前取得其他既有认证账号/员工锁而反转租户→账号→员工的顺序。用户名限定为1–64个小写ASCII字母、数字、点、下划线、连字符，首字符只能为字母或数字；不静默改名或大小写折叠。

## 代价与后续

同租户登录和管理串行化，哈希期间持锁，换取可审计撤销语义；这适用于低并发本机内测，不能据此宣称共享服务器吞吐达标。失败窗口采用固定的首次失败/首次尝试窗口，不实施分布式IP策略；不信任转发头。会话历史保留，只有活动数量有界，本轮不增加后台历史清理政策。数据库连接池、可信调用方与 API 的请求体限额仍需装配层正确配置。

Cookie、Origin、Host、CSRF路由、账号CLI、备份恢复和浏览器状态清理在后续任务消费此接口；本 ADR 不代表已完成这些验收。无真实 Provider、消息外发或真实凭证加载。
