# ADR 0095：员工本人阿里企业邮箱连接与受控发送

状态：已接受（2026-10-14）。用户明确要求将客户转给齐凯，并由其使用 sales@jslingte.com 联系；邮箱服务商由用户确认为阿里企业邮箱。

## 决策

本人邮箱页提供显式连接表单。密码只在 HTTPS 请求、受信认证插件与服务器私有文件间流动，提交立即清空页面，不进入模型、业务表、账本、错误正文或浏览器持久存储。绑定以当前 tenant、employee、user 三项为范围，文件目录 0700、文件 0600。当前在职身份必须通过服务器校验，连接期间持员工行锁；不能用开发请求头冒充真实会话。

新增 email.aliyun.connect 插件经过 Gateway 的 tenant、permission、idempotency、rate_limit，EXECUTING 提交后才执行固定官方 SMTP/IMAP TLS 认证，成功后发布私有绑定。认证不发送测试邮件、不注册或认证发件身份、不自动启用回复。

既有 email.send 保留六段检查、联系人可达性、Campaign 审批、抑制、额度和确定性关联头。仅增加执行阶段连接器解析端口；阿里邮件必须来自当前员工本人绑定的精确地址，不按失败切换邮箱。部署明确配置的原 Gmail 地址仍走原连接器，其余地址走阿里本人绑定。现有 GmailSendRequest/Result 作为兼容邮件信封契约复用，不把阿里结果显示为 Gmail 结果。

人工发送权限由客户当前归属决定，不再由 Campaign 创建者决定；老板保留企业管理权限，经理按当前负责人和团队判断。客户转交另遵守 ADR0094 的在途发送与旧任务检查。

SMTP 明确接受才记录已发送；这不等于对方收到。DATA 后未知结果只能按原 Message-ID 和幂等头在 Sent 查找，不能自动重发；查无结果也不能当作未发送。连接器只读所需已发送邮件头，不同步整个个人邮箱，不读取客户回复正文。

## 运行与验收边界

只有部署显式创建 profile 配置目录内的 `aliyun-mail` 私有目录才装配该能力。启用目录不表示任何人已连接邮箱或发件条件已满足。真实邮箱凭证须由员工在 UI 输入；联系人验证、发件域认证和 Campaign 均须各自真实通过后，才能发送客户邮件。不得用测试 fixture 或手工改库代替。

阿里连接器支持认证、单封发送、只读对账；阿里入站正文同步和自动回复不在本次已完成能力内。服务器备份还须单独保留私有凭证目录，不把它打入代码发布包。
