# 权限模型

两层组合：**RBAC 管「能做什么类型的事」，ABAC 管「能碰哪些数据」。** 单独用任何一层都不够——销售 A 和销售 B 角色相同，但不能互看对方的客户。

---

## 一、RBAC：角色

| 角色 | 定位 |
|---|---|
| `boss` | 下达指令、审批、查看全公司 |
| `manager` | 管理下属、接收升级、审批范围内事项 |
| `sales` | 跟进自己负责的客户与机会 |
| `sourcing` | 处理寻源案例与供应商 |
| `product` | 维护产品与供应能力 |
| `finance` | 成本、报价、利润 |
| `viewer` | 只读 |

角色决定可调用的操作类别，例如 `sales` 可以创建邮件草稿，不能审批报价。

---

## 二、ABAC：业务范围

同一角色的两个人可见数据不同，由属性决定：

```text
国家 / 地区      团队        产品类别
需求类别         客户归属     Campaign
部门             语言
```

例：销售张三是 `sales` 角色，属性限定为 `countries: [United States]`、`need_categories: [hardware, metal components]`。他看不到德国客户，也看不到食品类需求。

---

## 三、典型权限组合

以销售为例，这几条约束最容易被实现漏掉：

```text
可以   看自己负责的客户与机会
可以   看销售视图的产品卡（价格范围、卖点、MOQ、交期）
可以   创建邮件草稿
不可以 看供应商与真实采购成本
不可以 审批自己的低利润报价
不可以 查看其他团队的全部客户
不可以 修改发件身份配置
```

产品三视图（内部 / 销售 / 客户）是权限在数据层的直接体现，见 [01-domain-model.md](01-domain-model.md#八产品的三个视图)。**客户视图永不包含供应商和内部成本**——这条要在序列化层强制，不能靠前端不显示。

---

## 四、Context Builder：给模型的数据也要裁剪

「模型能处理所有数据」不等于每次把整个数据库塞给它。每次运行只加载当前任务需要的数据，并显式声明可用与禁用的工具：

```yaml
user: 张三
role: sales
allowed_countries: [United States]
current_account: [Acme Hardware]
allowed_tools:
  - customer.read
  - conversation.read
  - product.search
  - need.update
  - email.draft
blocked_tools:
  - employee.read_all
  - email.send_unapproved
  - quote.approve
```

**关键点**：模型的权限是用户权限的子集，永远不能超出。老板会话里的 Agent 权限大，销售会话里的 Agent 权限小。实现细节见 `agent-runtime/context-builder/`。

`blocked_tools` 要显式写出，不能只靠 `allowed_tools` 白名单——显式禁用是给 Tool Gateway 的第二道校验，也是给审计留的证据。

## 五、租户隔离

Phase 1 单租户，但隔离必须预埋（硬边界 8）：

- 所有表带 `tenant_id`
- 所有查询强制租户过滤，**缺失即安全缺陷**
- 租户上下文从请求或任务上下文传入，不从全局变量取
- 跨租户查询只允许平台运维专用路径，且必须留审计

推荐做法：Repository 层统一注入租户过滤，不依赖每个查询点自觉。

---

## 六、Lead Ownership Lock

防止多个员工重复联系同一家公司——重复触达会让客户觉得公司管理混乱，也浪费成本。

分配优先级（从高到低）：

```text
1. 老板手动指定
2. 已有客户历史负责人
3. 国家 + 需求类别
4. 国家 + 客户类型
5. 语言与时区
6. 当前员工工作量
7. 备用员工
8. 经理待分配池
```

锁的粒度是**企业**，不是联系人——同一家公司的不同联系人必须归同一个员工。

---

## 七、审批权限

必须人工审批的动作清单见 [AGENTS.md](../../AGENTS.md#六必须人工审批的动作)。权限模型在此处的额外要求：

- **不能自我审批。** 销售不能批自己的低利润报价，员工不能批自己的承诺。
- 审批权限按金额和风险分级，而不是一律给老板——否则老板会成为瓶颈，进而有人绕过流程。
- 审批记录不可删除，含审批人、时间、看到的内容快照。

---

## 八、实现要求

1. **默认拒绝。** 没有明确授权的操作一律拒绝，不要用「没写就是允许」。
2. **在服务层判权，不在 API 层判权。** Worker 和工作流也会调用同一批服务，只在 router 上加装饰器会漏。
3. **权限检查结果写审计。** 尤其是被拒绝的调用——它是排查问题和发现攻击的主要线索。
4. **Tool Gateway 是最后一道闸。** 即便上游判权有漏，Gateway 也会独立校验租户、权限、审批状态，见 [04-tool-gateway.md](04-tool-gateway.md)。
