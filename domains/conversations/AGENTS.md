# domains/conversations/ —— 会话域（浅）

## 职责

跨渠道会话与消息、**回复分类枚举**（智能收件箱的核心）、下一问选择接口。

## 回复分类是本域最重要的资产

收到客户回复后系统的第一个判断就是「这是哪类回复」，因为**每一类对应一个确定的系统动作**。分类错了，后面全错——把退订当成没兴趣继续发第三封，就是投诉。

14 类与对应动作写全在 `models.ReplyCategory`，摘要：

```text
分类                      系统动作
─────────────────────────────────────────────
明确兴趣 / 愿意继续        停序列，进入需求确认
要求资料 / 要求报价 /      停序列 + 触发人工接管
要求样品 / 提供规格
无当前需求                停序列，标记未来可重启
以后可能有需求            停序列，建跟进任务
介绍其他联系人            停序列，新联系人走验证流程
拒绝                      停序列
退订                      停序列 + 抑制名单
退信                      按硬/软处理（见 outreach）
自动回复                  不算回复，序列继续
投诉                      停序列 + 抑制 + 计入身份信誉
```

**自动回复是唯一「不算回复」的类别**——把 out-of-office 当回复会错停序列，也会污染回复率统计。

## 下一问选择：一次只问最关键的一两项

客户说 "We may need hinges."：

```text
好：Could you share the intended application and approximate size range?
差：请提供数量、材质、尺寸、颜色、包装、认证、目标价、付款方式和交期。
```

十几个问题的审讯式追问会直接终结对话。`NextQuestionSelector` 接口的输入是需求完整度的缺失字段（`missing_fields_for_sourcing`），输出是**最多两个**该问的问题主题——具体措辞由 `agent_runtime/qualification_agent` 生成。

## 依赖白名单

```text
允许   shared.*        禁止   其他 domains/*、外部 SDK
```

分类的模型调用在 `agent_runtime`，本域定义类别与动作映射、存分类结果。
