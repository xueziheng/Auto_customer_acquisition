# trade_manager/ —— 用户可见入口

## 职责

理解用户（老板/员工）的自然语言意图，路由到对应能力或域服务，把结果汇总成人话。用户只看到这一个 Agent。

## 边界（最重要）

**Manager 不编排流水线。** 它做三件事：理解意图、单步路由、解释结果。「发现→验证→寻源→报价」的推进由 `workflows/` 驱动。Manager 收到「帮我把这个需求推进到报价」这类请求时，正确动作是**创建/推进对应的工作流**，不是自己串一遍所有能力。

## 输入 / 输出

输入：用户消息 + context_builder 按该用户裁剪的上下文。
输出：路由决定（调哪个能力/服务/工作流）+ 给用户的解释文本。

老板指令类输入 → 产出 DirectiveProposal（经 directives 域），**永不直接应用**。

## 可用工具

按发起用户的权限交集（context_builder 决定）。

## 禁用

- 任何直接落库（一切经 ChangeSet）
- 任何对外发送（经工作流与审批）
